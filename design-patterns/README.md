# Паттерны проектирования на C# / .NET

Учебный репозиторий с конспектами и рабочими примерами классических паттернов проектирования (Gang of Four), адаптированными под платформу .NET. Структура и подбор паттернов основаны на книге **Сергея Теплякова «Паттерны проектирования на платформе .NET»**, конспекты написаны своими словами с собственными примерами кода.

> Этот конспект также собирается как сайт-книга на **Material for MkDocs**: с полнотекстовым поиском, оглавлением, светлой и тёмной темами.

[Открыть сайт-книгу на GitHub Pages](https://666mxvbee.github.io/DesignPatterns/)

## Зачем это нужно

Паттерн проектирования - это не готовый кусок кода, а **проверенное временем решение типовой проблемы проектирования**, описанное на уровне классов и их взаимодействия. Паттерны дают:

- **общий словарь** для команды (сказать "тут просится Strategy" быстрее, чем описывать конструкцию словами);
- набор **проверенных решений**, которые не нужно изобретать заново;
- понимание **компромиссов** - у любого паттерна есть цена (доп. абстракции, косвенность вызовов), и важно знать, когда она оправдана, а когда нет.

Важно: паттерн - это не самоцель. Задача не "применить как можно больше паттернов", а решить конкретную проблему изменяемости, расширяемости или связанности кода. Часто более простое решение (делегат, обычный `if`, метод расширения) лучше, чем формальная реализация паттерна "по учебнику".

## Структура репозитория

```
design-patterns/
├── creational/     - порождающие паттерны (как создавать объекты)
├── structural/      - структурные паттерны (как компоновать объекты в структуры)
└── behavioral/      - паттерны поведения (как объекты взаимодействуют и распределяют обязанности)
```

В каждой папке категории лежит `README.md`, объясняющий, зачем нужна именно эта категория паттернов. Внутри - по одной папке на паттерн, а в ней:

- `<Pattern>.cs` - минимальный, но рабочий пример на C#, который можно скомпилировать и запустить;
- `README.md` - конспект: проблема, решение, структура, плюсы/минусы, когда применять, примеры из .NET Framework/BCL.

## Оглавление

### Порождающие паттерны ([creational](./creational/README.md))

| Паттерн | Описание |
|---|---|
| [Singleton](./creational/singleton/README.md) | Гарантирует единственный экземпляр класса и глобальную точку доступа к нему |
| [Factory Method](./creational/factory-method/README.md) | Делегирует создание объекта подклассам через переопределяемый метод |
| [Abstract Factory](./creational/abstract-factory/README.md) | Создаёт семейства связанных объектов без указания конкретных классов |
| [Builder](./creational/builder/README.md) | Пошагово собирает сложный объект, отделяя конструирование от представления |
| [Prototype](./creational/prototype/README.md) | Создаёт новые объекты копированием заранее настроенных прототипов |

### Структурные паттерны ([structural](./structural/README.md))

| Паттерн | Описание |
|---|---|
| [Adapter](./structural/adapter/README.md) | Преобразует интерфейс одного класса в интерфейс, ожидаемый клиентом |
| [Bridge](./structural/bridge/README.md) | Разделяет абстракцию и реализацию на независимо развиваемые иерархии |
| [Facade](./structural/facade/README.md) | Даёт простой унифицированный интерфейс к сложной подсистеме |
| [Decorator](./structural/decorator/README.md) | Динамически добавляет объекту новое поведение, оборачивая его |
| [Composite](./structural/composite/README.md) | Компонует объекты в древовидные структуры и работает с ними единообразно |
| [Flyweight](./structural/flyweight/README.md) | Экономит память, разделяя повторяющееся состояние множества объектов |
| [Proxy](./structural/proxy/README.md) | Подставляет объект-заместитель, контролирующий доступ к другому объекту |

### Паттерны поведения ([behavioral](./behavioral/README.md))

| Паттерн | Описание |
|---|---|
| [Strategy](./behavioral/strategy/README.md) | Инкапсулирует семейство взаимозаменяемых алгоритмов |
| [Template Method](./behavioral/template-method/README.md) | Задаёт скелет алгоритма, отдавая отдельные шаги подклассам |
| [Mediator](./behavioral/mediator/README.md) | Инкапсулирует взаимодействие множества объектов в отдельном посреднике |

| [Memento](./behavioral/memento/README.md) | Сохраняет и восстанавливает состояние объекта без нарушения инкапсуляции |
| [Visitor](./behavioral/visitor/README.md) | Добавляет новые операции над структурой объектов без изменения самих классов |

## Как читать код в примерах

Каждый `.cs`-файл самодостаточен и содержит:
1. Абстракции и реализации паттерна.
2. Класс `Demo` со статическим методом `Run()`, который показывает паттерн в действии (аналог `Main`, чтобы файлы можно было при желании объединять в одном проекте без конфликта точек входа).

Примеры относятся к конкретным паттернам, поэтому их удобнее размещать непосредственно в соответствующих главах.

## Сайт-книга

Для локального просмотра перейдите в родительскую папку проекта, установите зависимости и запустите сервер:

```powershell
cd ..
python -m pip install -r requirements.txt
python -m mkdocs serve
```

Статическая сборка создаётся командой:

```powershell
python -m mkdocs build --strict
```

Готовые HTML-файлы появятся в соседней папке `site`.

При каждом push в ветку `main` workflow `.github/workflows/pages.yml` собирает сайт заново и публикует его через GitHub Pages.
